# POLICY —— 仓库红线与 CI 门禁

> 本文件是**规范性**文档（RFC 2119 语义：MUST / MUST NOT / SHOULD）。
> 任何章节、任何子 agent、任何未来贡献者都不得例外。`tools/check_policy.py` 是它的**可执行化身**：
> 文档与检查器不一致时，以检查器为准，并必须同步修改本文件。

## 1. 依赖红线（最重要的一条）

`docs/CHAPTERS.md` §0 写死了本项目的存在理由：

> **不用现成求解器替代自研实现**。SciPy / NumPy / PyTorch 只作为对拍参照物存在。

为了让这条口号变成**机器可验证的约束**，规定如下：

| 规则 | 内容 | 强制方式 |
|---|---|---|
| **P1** | `import scipy` / `from scipy ...` **只允许**出现在 `numcore/reference/` 下的文件（**全仓库**，含 `tests/`、`tools/`、`server/`） | AST 静态检查 |
| **P2** | `numpy.linalg.*`、`numpy.fft.*` 亦**只允许**出现在 `numcore/reference/`（全仓库）；`numcore/` 其余部分连"借用现成求解器"的入口都不存在（`numpy.random` 由 P4 单独管） | AST 静态检查（属性链） |
| **P3** | `numcore/`（`reference/` 除外）MUST NOT 使用 `numpy` 的"成品算法"：`polyfit / polyval / poly1d / roots / interp`、`trapezoid / trapz / gradient / convolve / correlate`、`histogram / histogram2d / histogramdd / bincount / digitize / corrcoef / cov`、`lstsq / solve / inv / det / slogdet / eig / eigvals / eigh / eigvalsh / svd / svdvals / qr / cholesky / norm / cond / matrix_rank / pinv / expm / kron / tensordot`，以及 `from numpy.polynomial import ...` | AST 静态检查（属性黑名单 = `tools/check_policy.py::P3_ATTRS`，实测逐条对齐） |
| **P4** | `numcore/` MUST NOT 直接使用 `numpy.random`；随机数一律经 `numcore.utils.rng(seed)` 取用（集中确定性 + 可复现） | AST 静态检查（`import numpy.random`、`from numpy.random import ...`、`numpy.random.*` 三种写法都拦） |
| **P5** | `numcore/` MUST NOT import `matplotlib / pandas / sympy / mpmath / sklearn / numba / torch / tensorflow / jax / statsmodels`（`reference/` 可有 sympy、mpmath，用于精确解与高精度对拍） | AST 静态检查（`BANNED_MODULES["P5"]`） |
| **P6** | `numcore/` 的公开函数 MUST 是纯函数：无 IO、无全局可变状态、无 `print`、无 `open/os/sys/subprocess/socket`、无 `global`、无动态 `import_module` | AST 静态检查（IO 名称黑名单 + `Global` 节点 + 动态 import） |
| **P7** | `viz/` MUST NOT 引入任何运行期第三方依赖（`node_modules` 只允许 `typescript`、`@types/node` 两个 devDependency） | 检查 `package.json` + `viz/**/*.ts` 的 import 扫描（`viz/tests/` 内的 `node:*` 除外） |
| **P8** | `viz/chapters/**` MUST NOT 自行实现物理/数值算法：只能消费后端帧，或调用 `viz/shared/src/numeric/` 中**已通过对拍**的函数，且**同文件**必须标注 `// preview-approx`（UI 据此打"前端近似预览"徽标） | import 扫描：`viz/chapters/**` 里出现 `.../numeric/...` 而不含 `preview-approx` 即违规；对拍由 G7 兜底 |
| **P9** | **（保留编号，非机器检查）** 章节前端 MUST NOT 硬编码数值结果充当"数据"；场景必须由帧驱动 | 无自动检查：由 P7/P8 静态检查 + G8 视觉回归（快照由真前端模型消费后端帧生成）间接兜底，剩余部分靠评审 |
| **P10** | `numcore/`、`server/`、`viz/` MUST NOT import `numcore.reference`：参照物只允许出现在 `tests/` 与 `tools/` 里（对拍是测试的事，交付物不许借参考实现） | AST 静态检查（`import` 与 `from ... import`） |
| **P11** | **（空号，从未启用）** 无对应检查；编号保留以免已引用的 P10/P12/P13 被重新编号 | — |
| **P12** | `.gen.ts` 生成物 MUST 在前 600 字符内含"由…生成 / generated by / 请勿手改 / DO NOT EDIT"之一（防止有人把生成物当手写文件改） | 文本扫描（`_GEN_HEADER_RE`） |
| **P13** | **五件套完整性**：只要"开了章"（`chapters/<id>/` 目录或 `server/chapters/<id>.py` 存在），就必须有 `chapters/<id>/notes.tex`（且含 `\begin{theorem}`）、`chapters/<id>/pitfalls.md`（≥ 800 字）、`chapters/<id>/asserts.yaml`；未开的章不报 | 文件存在性 + 正则 + 字数统计 |

**允许用 numpy 做什么**：`ndarray` 作为容器、逐元素算术、切片/广播、`np.dot`/`@`（当作 BLAS 原语）、`np.concatenate/stack/zeros/empty/arange/linspace/meshgrid/where/clip/abs/sqrt/exp/log/sin/cos/sum/mean/max/min/argmax/all/any/isfinite/isnan/cumsum/prod/outer/einsum`（缩并原语）、`np.linalg` 之外的 `np.errstate`。这些是"语言的一部分"，不是"求解器"。

> 判定口径：**如果一个调用直接给出了本章要教的那个算法结果，它就是被禁的。**
> 例如 2.5 章要教 FFT，则 `np.fft.fft` 被禁；1.2 章要教 LU，则 `np.linalg.solve/lu` 被禁。
> 反过来，用 `@` 做矩阵乘法实现自己的 LU 是允许且鼓励的。

### 例外登记

| 例外 | 位置 | 理由 | 检查器中的体现 |
|---|---|---|---|
| P6 豁免 | `numcore/verify/plugin.py`、`numcore/verify/report.py` | 它们是**测试基础设施**（pytest 插件与断言报告落盘），IO 被限制在具名函数（`write_report`、pytest 钩子）内，不参与任何数值计算 | `P6_EXEMPT_FILES`，并在 CI 输出中显式列出 |
| P4 豁免 | `numcore/utils.py` | 它是 `numpy.random` 的**唯一合法封装点**（`rng(seed)`），集中管理确定性 | `ALLOWED_PATHS["P4"]` |
| P1/P2/P5 豁免 | `numcore/reference/**` | 参照物层的存在意义就是调用成熟实现 | `ALLOWED_PATHS` |

**规则作用域**（避免"一刀切"误伤；逐条对应 `tools/check_policy.py::rule_applies`）：

* P1、P2、P4 —— **全仓库**（含 `tests/`、`tools/`、`server/`）：Python 侧的"现成求解器"只有 `numcore/reference/` 可以用，
  测试想对拍也必须经由它，这样"边界"只有一个。
* P3、P5、P6 —— 只约束 `numcore/`：测试与工具里用 `numpy.polyfit` 做交叉验证是**合法且鼓励**的
  （它们不是交付的自研实现）。
* P7、P8、P12 —— 只约束 `viz/`（P7 另查根 `package.json`；P8 只查 `viz/chapters/**`）。
* P10 —— 只约束 `numcore/`、`server/`、`viz/`；`tests/` 与 `tools/` 正是**必须**用参照物的地方。
* P13 —— 只看 `chapters/<id>/` 与 `server/chapters/<id>.py` 判定"哪些章开了"。

**编号范围**：规则号一直到 **P13**，但**不等于 13 条都机器强制**。`tools/check_policy.py` 的
`RULE_DOC` 里恰好 11 条被强制执行（P1–P8、P10、P12、P13）；P9 保留为评审项、P11 是空号。
`check_policy.py` 通过时会打印 `策略检查通过：11 条规则、0 违规`——这个数字就是上面这 11 条。

行内豁免 `# policy: allow P<n> <理由>` 必须在 `tests/policy/allowlist.txt` 登记，
否则 `check_policy.py` 报 `ALLOWLIST` 违规——防止有人用注释悄悄开后门。
检查器用 `tokenize` 识别**真正的注释**，不会被字符串/文档里的同样文字骗过。

确需例外时，必须在源码处写 `# policy: allow <规则号> <理由>`，并在 `tests/policy/allowlist.txt` 中登记；
检查器只承认**已登记**的豁免。禁止行内豁免不登记。

## 2. 五件套完整性（每章）

一章 = 五个交付物，缺一不可，路径固定：

| # | 交付物 | 路径 | 缺失判定 |
|---|---|---|---|
| 1 | 推导笔记 | `chapters/<id>/notes.tex` | 文件不存在，或 `\begin{theorem}` 数为 0，或编译失败 |
| 2 | 核心实现 | `numcore/<area>/...`（见 `docs/chapters.yaml` 的 `modules`） | 模块不存在或 import 失败 |
| 3 | 交互可视化 | `viz/chapters/<id>/*.viz.ts` + `manifest.gen.ts` | 可视化数 ≠ `chapters.yaml` 的 `viz:` 声明 |
| 4 | 数值断言 | `tests/<id>/` + `chapters/<id>/asserts.yaml` | 声明与实跑**双向**不匹配 |
| 5 | 防误导分析 | `chapters/<id>/pitfalls.md` | 文件不存在或少于 800 字 |

`tools/gen_progress.py` 依此生成 `docs/PROGRESS.md` 与站点进度条。

## 3. 断言纪律

- A 类（解析对拍）：**必须**给出收敛阶，且实测阶 ∈ 理论阶 ± 0.1（`numcore.verify.assert_order`）。
- B 类（不变量）：**必须**声明容差来源（机器精度 / 解析容差 / 问题规模推导），不得"试出来的容差"。
- C 类（收敛率/阈值）：**必须**由脚本判定；阈值类断言 SHOULD 用 `numcore.verify.find_threshold` 二分实测，而不是把理论值抄回来当实测值。
- 每条断言 MUST 通过 `@assertion(...)` 装饰器登记，声明 `theory`（理论值/理论阶）与 `measured`（实测），
  失败信息 MUST 同时打印两者与差值。禁止 `assert True` 式占位。
- 每章 `asserts.yaml` 中声明的断言 id 与 pytest 收集到的 id MUST 双向一致。
- **skip 不是通过**：`pyproject.toml` 开的是 `--strict-markers --strict-config`
  （`--strict` 只是 `--strict-markers` 的**废弃别名**，本仓库不用它），它不会把 skip 变成失败。
  现状是**存在且仅存在**下列 4 处有理由的 skip，除此之外 MUST NOT 新增；
  确需新增时必须在 code review 里写明"为什么它不是掩盖失败"，并更新本节：
  | # | 位置 | 触发条件 | 为什么合理 |
  |---|---|---|---|
  | 1 | `tests/test_gif.py`（`requires_pillow` 标记） | 环境里没有 Pillow | Pillow 只用于**独立交叉验证**自研 GIF 编码器；缺它时降级为"少一层外部验证"，不是掩盖失败（本环境实测 Pillow 12.0.0 已装，该 skip 不触发） |
  | 2 | `tests/test_png.py`（`requires_pillow` 标记） | 同上 | 同上（自研 PNG 编解码的交叉验证） |
  | 3 | `tests/test_app.py::test_static_symlink_*`（2 处） | 平台不允许创建符号链接（`os.symlink` 抛 `OSError`） | 测的是"软链越界要被 403"这一安全属性，没有符号链接就无从构造用例；Windows 无权限时只能跳过 |
  | 4 | `tests/test_tools.py::test_real_asserts_report_is_reconciled` | **单文件**运行 pytest，本次会话的断言登记表不全 | 它断言的是"整跑后的报告能对账"；CI 永远整跑（G2 是 `pytest tests -q`），走不到这条分支 |

## 5. CI 门禁（`make ci` 全绿才算完成）

| 门 | 命令 | 通过标准 |
|---|---|---|
| G1 | `python3 tools/check_policy.py` | 0 违规（机器强制的 11 条：P1–P8、P10、P12、P13；P9 是评审项、P11 空号） |
| G2 | `python3 -m pytest tests -q` | 全绿；skip 只允许 §3 表里那 4 处有理由的，新增 skip 必须在评审里说明 |
| G3 | `python3 tools/run_asserts.py --no-run` | 声明↔实跑双向一致，全绿；`--no-run` 直接复用 G2 刚写好的 `dist/reports/assertions.json`，不重复跑一遍 pytest |
| G4 | `npm run typecheck` | `tsc --noEmit` 0 错误（`strict: true`） |
| G5 | `npm test`（CI 里先 `npm run build --silent`） | TS 单测（含 `.nlf` 解码、scene 校验、数值 helpers）全绿 |
| G6 | `python3 tools/gen_manifests.py --check && python3 tools/gen_colorscales.py --check` | **两类生成物都**与真源一致（无漂移）：manifest（`manifest.gen.ts`/`data/manifests`）+ 色标 LUT（`colorscale_data.gen.ts`/`colorscales.json`） |
| G7 | `python3 tools/parity.py` | Python↔TS 基准数据逐点一致（容差取自 `tests/parity/tolerances.yaml`）；失败时打印每个 case 的 `max\|Δ\|` 与点位数 |
| G8 | `python3 tools/precompute.py --n 6 --quiet && npm run scene --silent && python3 tools/visual_regression.py --check --require-scenes` | 场景/像素快照与基线一致（或已显式 `--update` 并附原因）。**三步必须一起跑**，理由见下 |
| G9 | `python3 tools/build_book.py --check` | 结构检查（`notes.tex` 有 `\begin{theorem}`、`\input{chapters/<id>/asserts_table}`、附表与 `dist/reports/assertions.json` 一致）+ 有 xelatex 时逐章/合并本编译通过、无未定义引用 |
| G10 | `python3 tools/gen_progress.py --check` | `docs/PROGRESS.md` 与仓库状态一致 |

**G3 的坑（argparse 前缀匹配）**：`tools/run_asserts.py` **没有** `--all` 这个选项。
argparse 默认允许**无歧义前缀**，`--all` 会被当成 `--allow-empty` 的唯一前缀而**静默接受**——
那正是"报告缺失也不算失败"的调试开关（实测：`--no-run --report /tmp/x.json` → exit 1；
加上 `--all` → exit 0）。所以 G3 MUST 写全 `--no-run`；给这类脚本加新选项时，
也要避免两个选项名互为前缀。

**G8 的三步为什么不能省**（`tools/ci.sh` 里就是这三步一条命令）：

1. `tools/precompute.py --n 6` 先在 `data/frames/` 落 L3 帧（`--n 6` 与基线文件名里的时刻**同契约**，改它=改基线）；
2. `npm run scene`（`dist/viz/tests/scene/dump_scenes.js`）把帧喂给**真前端模型**，转储 `dist/scenes/**.json`；
3. `tools/visual_regression.py --check --require-scenes` 才拿这些场景去比基线。

只跑第 3 步：新检出里 `dist/scenes/` 是空的，`--check` 会走"场景缺失"的兜底路径——
**一张图都没比也能绿**（`--require-scenes` 正是为钉死这条而存在：0 个转储即失败）。
只跑第 1、2 步：等于只生成不比。所以三步是一个整体。

> **G6/G8/G10 的"漂移"类门禁是本项目的良心**：它们专治"文档说做了、其实没做"与"图好看但算错"。

## 6. 命名与风格

- Python：`snake_case`；公开 API 必须有 docstring，**docstring 第一行给数学定义**（不是功能描述）。
  例：`def lu(A): """PA = LU，其中 L 单位下三角，U 上三角。"""`。
- 数值核心函数签名统一为 `(输入数组, 关键字参数) -> 结果`，不在函数内做输入校验以外的副作用。
- TypeScript：`camelCase`；每个 viz 拆成两个文件——`viz/chapters/<id>/<viz>.model.ts`（纯：`Frame → Scene`，
  无 DOM、无 IO、可在 node 里直接测）与 `<viz>.viz.ts`（装配入口：把 manifest + model 交给共享渲染层，
  注册表按它统计"已实现"）。渲染层是**共享**的 `viz/shared/src/render2d.ts`（Scene → canvas）与
  `viz/shared/src/view.ts`（DOM 装配，章节无关）；**不**为每个 viz 单独建 `view.ts`。
- 中文注释解释**为什么**，英文标识符承载**是什么**。
- 提交信息：`<area>: <what>`（例：`core(linalg): 加入带部分主元的 LU 与增长因子`）。
