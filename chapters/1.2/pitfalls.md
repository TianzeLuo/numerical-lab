# 1.2 章会怎样骗你

这一章讲的是"解 $Ax=b$"这件最古老的事。正因为古老，它的图上全是**看起来懂了**的陷阱：
增长因子与条件数被混为一谈、行列式被当成病态程度的度量、自适应坐标把病态抹平成"很圆"、
采样量出来的"实测 κ"其实是采样分辨率。下面每一条都给出本章可视化里的具体现象与
**实测数字**，不是泛泛的注意事项。

## 1. 把"增长因子大"读成"解不准"（以及反过来）

`lu_heatmap` 的副轴画 ρ(k)，`pivot_strategy` 的主轴画 log10 ρ。ρ 大只说明**后向**误差的
界被放大，真正落到解上有多少位有效数字还要乘上条件数。两个方向的误读都能在图上复现：

* **反例矩阵 tiny_pivot**（`pivot_strategy` 里选它）：κ₁ **只有 4**，可无主元消元的
  ρ = 1e18、算出来的解前向误差 **1.0**（一位有效数字都不剩）；换成部分主元，ρ = 1、
  误差 0。这里 ρ 确实就是全部原因——所以"ρ 与误差无关"同样是错的。
* **Hilbert 矩阵**：三种主元策略的 ρ 全是 1、后向误差都在 6e-18 量级，可前向误差是
  1e-8 上下——原因是 κ₁(H₈) ≈ 3.4e10。**后向稳定 ≠ 解准**。

准确的判据只有一条：前向误差 ≲ κ(A)·ρ·u。缺任何一半都会得出相反结论。

## 2. 自适应坐标轴会把病态画成"很圆"

`unit_ball` 的主轴**故意固定**在 ±3。如果改成自适应，κ = 1e16 的椭圆会被拉伸到和单位圆
一样"圆"——条件数这种纯几何的性质在视觉上直接消失。这也是为什么本项目的
`axes[].autoscaled` 必须逐轴显式声明（规则 1）：**坐标轴是会撒谎的**，声明出来才有人负责。

反过来，固定轴也有代价：κ 大到一定程度椭圆会冲出画面。这时该看到的不是"图空了"，
而是溢出徽标（规则 4 的 `overflow`）——"看不见"必须与"不存在"区分开。

## 3. 采样量出来的 σmin 只会偏大，"实测 κ"是采样分辨率

`unit_ball` 里那个 `kappa_measured` 是在单位圆上均匀采样取最大/最小半径得到的。
实测：4001 个采样点在 κ ≥ 1e8 之后彻底饱和——κ = 1e8、1e12、1e17 都量出 **5258**。
原因不是浮点，而是几何：椭圆最扁的方向上，r(θ) 的变化率是 O(κ)，采样间隔只要不是
精确落在极值点上，量到的最小半径就远大于 σmin。误差是 O(Δθ²)（A 类断言
`test_sampled_singular_values_converge_quadratically` 钉住了这个上界），
但**误差常数**是随 κ 增长的，所以采样法在大 κ 处必然失效。

正经做法是用闭式/稳定的公式（本章用 2×2 的 σmin = |det A|/σmax，用除法换掉相减），
或者用 SVD（1.4 章）。把采样值抄进论文里当 κ 用，是这类图最常见的翻车方式。

## 4. κ 超过 1/u 之后，float64 里**不存在**那个小奇异值

κ = 1e17 时 A 的第二个奇异值约 1e-17，而 A 的元素是 O(1)：这个矩阵在 double 里
和奇异矩阵**无法区分**（任何算法都算不出那个方向）。所以：

* 图上画的"细椭圆"本身就是幻觉，它的短轴长度已经小于一个 ulp；
* 断言里绝不能出现"κ = 1e17 时误差 = 1e-1"这种"实测精度"——那不是算法的精度，
  是被表示误差截断后的随机结果；
* 唯一的诚实说法是"κ ≳ 1/u 时问题在 float64 下不可解"。

## 5. 右端项选得"不巧"，反例会失效

这是我自己踩到的坑，现在被测试钉住：tiny_pivot 矩阵
$\begin{pmatrix}10^{-18}&1\\1&1\end{pmatrix}$ 若取 b = (1,1)ᵀ，
**精确解恰好是 (0,1)ᵀ**——无主元消元"居然算对了"，前向误差 0.0，整个反例当场失效。
必须让 b 落在会被小主元放大的方向上（本章取 b = (1,2)ᵀ 这一族），
无主元解才现出原形（误差 1.0）。

推广开：任何"这个算法在这组数据上出错/不出错"的结论，都必须交代数据怎么来的。
本项目要求每个可视化显式声明 `dataSource`（规则 7），就是为了让这种"数据依赖"可见。

## 6. 残差恰好等于 0，而且 0 画不到对数轴上

`lu_heatmap` 那条前导块残差曲线经常**恰好**是 0：前导块上的重建用的是同一套运算，
舍入误差互相抵消。实测 n=8..16 的四个矩阵里，每一步的残差是 0 或 ~2e-16 两种。

这带来两个坑：
1. 对数轴画不了 0，直接送 `log10(0)` 会得到 -inf，前端会因为非有限点拒绝整个场景
   （规则 3 的"曲线必须有对照量"随之失守）。本章的做法是给一个明确的**地板 u/2**，
   并在 `meta.residual_exact_zero_steps` 里如实报告"有几步是精确 0"。
2. 看到"残差 = 0"就宣布"算法精确"是错的：它只说明这一次的重建刚好抵消，
   换个矩阵（或换个求和顺序）就会看到 1e-16。

## 7. 填充与数值无关，"填充少"不等于"更准"

`spy_ordering` 的副轴同时给出三种排序的 LU 后向残差——**三条都贴在同一水平线上
（~1e-16）**。排序只改变运算量与访存模式，不改变后向稳定性。所以"最小度填充最少，
所以它的解最可靠"是错的。

同时注意符号预测与数值事实的差别：全 1 矩阵的符号预测是 nnz(L+U) = 20，
而精确（有理数）消元只有 8——消元中的**精确抵消**让真实非零元变少了。
符号预测是结构上的上界，工程实现（SuperLU、UMFPACK）因此都要留余量、做动态判断。

## 8. 三个排序指标会互相打架

实测 2D Laplacian（k=8, n=64）：自然序 nnz(L+U) = 856 / 带宽 8 / 剖面 364，
RCM 的带宽最好，最小度的填充最少但带宽最差。所以"哪个排序更好"没有唯一答案：
优化内存带宽、优化浮点运算量、优化并行度是三个不同的目标。
`spy_ordering` 的角标同时给出 nnz、填充倍数、带宽、剖面、最大团与树宽上界，
就是要逼你**一起看**——只看一个数字的结论都不可靠。

## 9. 网格的真实树宽小于贪心给出的上界

k×k 网格的树宽恰好是 k（已知结论），而最小度消元过程中的最大团给出的上界
实测 ≥ k（k=4..10 全部成立，且往往更大）。上界不是等号：贪心算法不保证最优。
图上那个"最大团"角标是**上界**，写成"树宽"就夸大了。这也是断言
`test_treewidth_upper_bound_is_above_the_true_treewidth` 的写法为什么是"≥ k"而不是"= k"。

## 10. 时间轴是"消元步"，不是时间

`lu_heatmap` 与 `spy_ordering` 的时间轴是整数步 k，拖到 n-1 之后再拖**不会动**——
这不是卡了，而是范围内没有更多步骤（`meta.step` 会告诉你实际用的是哪一步）。
更隐蔽的一条：不同 n 的可视化共用同一个 `tMax = 15 / 195`，所以 n 小时时间轴
右半段是"空转"的。凡是要比较"第几步发生了什么"，必须读 `meta.step`，
不能读滑块位置。

## 11. 对数热力图上的"一片蓝"不代表接近零

`lu_heatmap` 的颜色是 log10|元素|。1e-16 与 1e-2 在这种色标下只是深浅不同，
肉眼看不出"这个元素已经小到会毁掉整列"。判据要读数字（`meta.pivot_min_abs`、
`meta.rho`），或者把 `pivot` 切到无主元、看它什么时候崩——**崩溃是突变的**：
ρ 在第 3 步之前一切正常，第 4 步全糊。稳定性问题不会"慢慢变差"给你预警。

## 12. 对角占优是**充分**条件：比值 < 1 不代表一定出事

滑块 `dominance` 的临界值标在 1.0（`critical: [1.0]`），因为严格对角占优
（比值 > 1）能保证乘子 |m| ≤ 1、ρ ≤ 2。但反过来不成立：实测把比值一路拖到 0.05，
ρ 也常常只有几到几十，矩阵并没有爆炸。把"充分条件"当成"充要条件"，
就会在回顾里写错结论（"占优比小于 1 必然不稳定"——错）。

准确的说法是：**比值 > 1 时你有保证；比值 ≤ 1 时你什么都没有**——没有保证，
但也没有判决。要判决就得具体算 ρ 或 κ。

## 13. "逐步残差"用的是**当步**的置换，不是最终置换

`lu_heatmap` 里有一条"前导块残差"曲线：`‖(前 m 阶参照块) − L_m U_m‖`。它测的是
"第 m 步时，消元已经算出的那块有多准"，所以参照块必须是**第 m 步那一刻**的矩阵。
这一条绊了三次，每次的表现都不一样：

1. **完全不换列**（`P·A` 直接取前导块）：完全主元的列置换被丢掉，残差量级是 **O(1)**，
   而它的正确值应当是 u 量级。实测（n=8，u/2 = 1.11e-16）：

   | 矩阵 | 策略 | 当步参照块 | 误用 `P·A` |
   |---|---|---|---|
   | 占优比 0.1 | 完全主元 | 1.84e-16 | **1.21e+00** |
   | 占优比 1.6 | 完全主元 | 1.79e-16 | **1.16e+00** |
   | Wilkinson | 完全主元 | 0.00e+00 | **2.00e+00** |
   | Hilbert | 完全主元 | 1.39e-17 | **2.50e-01** |
   | 构造 SPD | 完全主元 | 3.73e-16 | **9.22e-01** |

   注意部分主元那一列**看不出问题**（列置换是恒等），所以"只测一种策略"会漏掉它。
2. **用最终的 `P·A·Q`**：方向对了但仍是错的量——最终置换与当步置换不是一回事
   （后续的行/列交换会改变位置 ≥ m 的元素）。实测差距不大（我扫过的结构矩阵里最多 8 倍），
   但它是**另一个定义**，画在同一张图上就变成了"用最终结果解释中间过程"。
   现在后端用 `numcore.linalg.lu.leading_block_residuals()`：它在消元过程中维护一个
   **只做交换、不做消元**的参照副本（`ref_history`），所以每一步的残差都是当步定义。
3. **只看结论不看定义**：图上写"残差贴住 u"时，要能说清"哪一个矩阵、哪一步的哪个块"。

## 14. 奇异是一个**状态**，不是一个崩溃；NaN 连 `.nlf` 都写不出去

`unit_ball` 在剪切的临界点（`shear=2`）会让 `A = [[1, 2], [2, 4]]` 精确奇异，
`lu_solve` 抛 `ZeroDivisionError`；更隐蔽的是 γ 一路推高到 κ > 1/u 时，
前向误差之类的量会变成 `NaN`/`inf`。两条都必须当"要显示的事实"处理，而不是让它穿过去：

* **崩溃要变成状态**：捕获 `ZeroDivisionError`/`ValueError`，把解向量写成 `None`，
  `meta.singular = true`，`strings.status` 写"数值奇异：κ > 1/u，A 的浮点分解出现零主元"。
  这一帧照常构建、照常编码、照常渲染——它显示的是"这里没有有限解"这个事实。
* **NaN 连帧都存不下**：`.nlf` 的头部是 JSON，`json.dumps(..., allow_nan=False)`
  会在写盘那一刻抛 `ValueError: Out of range float values are not JSON compliant`，
  而错误信息完全看不出是**哪个量**没定义（1.1 章也踩过同一个坑）。
  现在 `Frame.validate()` 会提前拒绝非有限浮点，并直接点名
  `meta['x'] = nan 不是有限数——JSON 没有 NaN/Infinity，请用 None（null）表示"无有限值"`。
* **别用 `np.max` 检查"是否已经跑飞"**：`np.max` 遇到 NaN 会返回 NaN，
  于是 `np.any(|x| > 3)` 这类判据在 NaN 面前**静默为假**（溢出标记再也不会亮）。
  1.2 的 `unit_ball` 因此把判据写成
  `np.any(np.abs(np.concatenate([...])) > 3.0)`——`np.any` 对 NaN 的比较是 False，
  但"有 NaN"这件事本身已经由 `Frame.validate()` 挡住了。
* **顺序也要紧**：先判奇异、再算数值、最后判溢出。反过来会在奇异点上
  用一组 NaN 去算溢出标记，得到一个"看起来没事"的帧。
