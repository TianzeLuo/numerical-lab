# 1.1 章会怎样骗你

这一章讲的是浮点数、误差传播与问题条件——**图上的每一个量都能被读错一次**。
下面每一条都对应本章四个可视化里的具体现象，并给出**实测数字**（不是"注意事项"式的空话）。
文中的数字都可以用 `tests/1.1/` 里的断言复现。

先把三个量分清楚，后面所有陷阱都是它们的混用：

| 量 | 记号 | 谁决定 | 本章哪个 viz 画它 |
|---|---|---|---|
| 表示/舍入误差 | $u=2^{-53}$ | 硬件格式 | `float_zoom` |
| 算法误差 | $n u\sum\lvert x_i\rvert$、$2u\sum\lvert x_i\rvert$ | 求和顺序 | `summation_order` |
| 问题条件 | $\kappa(A)$、$(\lvert a\rvert+\lvert b\rvert)/\lvert a-b\rvert$ | 数据本身 | `cond_ellipsoid`、`cancellation` |

## 1. `float_zoom`：网格不均匀、落点在"错格"上、残差是相对谁算的

**陷阱 1a：把浮点网格看成等距的。** 主轴画的是"距中心的 ulp 偏移"，看起来是均匀刻度，
但它对应的真实数轴在**每个 2 的幂处间距减半**：实测 `ulp(1.0) = 2.22e-16`、
`ulp(1.0 - 1 ulp) = 1.11e-16`，比值恰好 **2.0**（7 个 binade 边界逐一验证）。
所以图里那条以最近的 2 的幂为中心的梯子在中心处会**突然掉一半**；把放大中心设在 0.3
这种非 2 的幂上时，整条梯子都在同一个 binade 内，间距比恒为 1——**这时"看不出不均匀"
是真相，不是画错**。

**陷阱 1b：把 `1e16 + 1 == 1e16` 当成渲染 bug。** `ulp(1e16) = 2`，加 1 恰好落在两个
可表示数的中点，ties-to-even 把它舍回偶数格点。帧里 `big_plus_one_unchanged = true`
（元数据）与 strings 里的说明是**必须**的：图上"看起来没变"是正确结果。
反过来说，如果哪张图画出了 `1e16 + 1 != 1e16`，那才是 bug。

**陷阱 1c：残差是相对谁算的？** 这是本章最阴的一条。

* `(fl(0.1) + fl(0.2)) - fl(0.3) = 5.551115123125783e-17`，**恰好是 1 个 ulp(0.3)**
  （ulp 距离实测 = 1）——这是大家熟悉的那个数；
* 但把它和**精确有理数** $3/10$ 比，差是 `4.4408920985006264e-17`，不是 5.55e-17。
  差的那 `1.1102230246251566e-17` 是 `fl(0.3)` 自己的表示误差
  （`fl(0.3) = 0.2999999999999999888977698`，精确十进制展开见帧的 strings）。

副轴画的是**对数学值 $k/10$** 的残差，所以 $k=3$ 处的高度是 4.44e-17；
而帧的 `meta.residual_0102_03` 是 5.55e-17。两个数都对，**比的对象不同**。
把它们混起来，就会得出"图上的曲线和教科书对不上"这种假故障。

**陷阱 1d：对数轴上"误差为 0"的点。** 残差在 $k=0,5,45$ 三处**精确为 0**，
但 log 轴画不出 0，帧里把它们按地板 $u/2\cdot\lvert k/10\rvert$ 抬起显示
（`meta.residual_floor`）。地板值与"真的有误差"在图上同一个高度——
判据只能是看它是否随 $k$ 增长，不能看它离底边多近。

## 2. `cancellation`：抵消放大的是**输入**误差，不是减法

**陷阱 2a：把爆炸的曲线读成"减法算错了"。** Sterbenz 引理说
$b/2 \le a \le 2b$ 时 $a-b$ 在浮点里**精确**：实测 2000 例的减法相对误差最大值
**0.0**（帧里那条恒为地板的曲线就是它）。被放大的是输入自带的相对不确定度
$\delta_{\rm in}$，倍数是 $(\lvert a\rvert+\lvert b\rvert)/\lvert a-b\rvert$。
$a=1,\ b=0.999999$ 时：$\delta_{\rm in}=5\times10^{-16}$（16 位十进制输入）、
$\lvert a-b\rvert=10^{-6}$、放大后实测相对误差 $3.33\times10^{-10}$，
剩余有效位 **9.30** 位——**再好的算法也救不回来**，因为误差已经在输入里了。

**陷阱 2b：把"剩余位数"当成对本次计算的误差测量。** 它只是先验估计
$\log_{10}(\lvert a-b\rvert/(u\,M))$。当它显示"还剩 3 位"时，图上那两个数本身
就已经不可信了。反向的误读同样致命：$\delta_{\rm in}$ 取 16 位时
$u = 1.11\times10^{-16}$ 与 $\delta_{\rm in}=5\times10^{-16}$ 是同一量级，
所以"剩余位数"永远不会超过约 15.95 位——**屏幕上不可能出现 16 位有效数字**。

**陷阱 2c：同量级的数据看不出抵消的兄弟问题。** 用 `uniform(-1,1)` 抽三元组算
$(a+b)+c$ 与 $a+(b+c)$，3000 组里 **2940 组**两个结果逐位相同——加法不结合这件事
在同量级数据上几乎不可见。把量级铺开到 $2^{-30}\sim2^{0}$ 之后，3000 组里有
**654 组**不同，偏差最大达到界的 **0.9969 倍**（界 $2u\sum\lvert x_i\rvert$）。
"我在自己的数据上没看出问题"从来不是证据。

## 3. `cond_ellipsoid`：自适应轴、目标 κ、采样饱和、κ ≳ 1/u

**陷阱 3a：自适应坐标轴把病态画成"很圆"。** 主轴**故意固定**在 ±3：
$\kappa=10^{8}$ 的椭圆短半轴只有 $1.3\times10^{-8}$，自适应之后会被拉到和单位圆一样大，
条件数这种纯几何的性质在视觉上直接消失。代价是椭圆会冲出画面——这时该看到的是
`meta.overflow` 徽标，而不是"图空了"。

**陷阱 3b：把"实测放大比远小于 κ"读成"界太松"。** 在 720 个方向上实测
$(\lVert\Delta x\rVert/\lVert x\rVert)/(\lVert\delta b\rVert/\lVert b\rVert)$ 与 $\kappa_2$ 的比值：
**最大 0.99997、中位数 0.19**。界是对**所有**方向的保证，随机方向一般不在最坏方向上；
默认帧（$\kappa=10^8$、30° 方向）只有 $0.36$，即 $6\times10^{-9}\kappa$——
**这不是界松，这是方向不对**。想看到界被逼近，得把 $\delta b$ 转到敏感方向。

**陷阱 3c：用采样量 κ 会饱和。** 在单位圆上均匀取 361 个点量半径，
$\kappa$ 从 $10^4$ 涨到 $10^8$ 时量到的 $\kappa$ 全是 **239.6**——因为最扁方向上的
$r(\theta)$ 变化率是 $O(\kappa)$，采样点碰不到极值方向。误差是 $O(\Delta\theta^2)$，
但常数随 $\kappa$ 增长。本章的 $\kappa_2$ 因此走闭式/幂迭代，采样的结果只用来画椭圆。

**陷阱 3d：`target` 不是 `measured`。** 帧里参数叫"目标 $\kappa$"，但 `shear` 族的实测
$\kappa_2$ 与目标并不相等：target $10^8$ → 实测 $5.877\times10^7$；`graded` 族 target
$10^4$ → 实测 $40002\approx4\kappa$；`triangular` → $20000=2\kappa$；`diagonal` 精确相等；
`rotation` 恒为 1。帧的元数据里 `kappa_target` 与 `kappa_measured` 必须**同时**出现，
只写一个就是在撒谎。

**陷阱 3e：转置不变性只对 2/F 范数成立。** 实测：$\kappa_1(A)=4.6649$、
$\kappa_1(A^\top)=6.5224$（差 40%），而 $\kappa_\infty(A)=6.5224$——因为
$\kappa_1(A^\top)=\kappa_\infty(A)$。把"转置不改变条件数"当成对所有范数成立，
会写出一个偏差 40% 的"回归测试"，然后花一整天找那个不存在的 bug。

**陷阱 3f：$\kappa\gtrsim1/u$ 之后没有"更准"这回事。** `shear` target $10^{14}$ 时
$\kappa u=6.5\times10^{-3}$；再往上（$\kappa\gtrsim9\times10^{15}$）$A$ 在 float64 里
和奇异矩阵无法区分，椭圆与实测曲线都只是舍入的产物。帧用 `meta.kappa_u ≥ 1` 标出来——
**"图上还有曲线"不等于"问题还可解"**。

**陷阱 3g：稳定 ≠ 准。** 同一族矩阵上：前向误差从 $1.3\times10^{-16}$（$\kappa\approx59$）
涨到 $1.4\times10^{-4}$（$\kappa\approx5.9\times10^{13}$），实测阶 1（$\le0.5\kappa u$）；
而后向误差始终 $\le0.1u$、与 $\kappa$ **无关**。两条曲线必须一起看。

## 4. `summation_order`：Kahan 不是万能药，但"乱序让它失效"也是错的

**陷阱 4a：把"乱序会让 Kahan 失效"当定理。** Kahan 的误差界
$(2u+O(nu^2))\sum\lvert x_i\rvert$ 对**任意顺序**成立。实测：6 个种子下把项做确定性置换后
误差与串行之比 **1.000**（同量级）。散发这条都市传说的人，真正想说的是下一件。

**陷阱 4b：真正失效的是并行归约，而且它会被"看不出来"掩护。**
$big=10^{16}$、$small=10^{-3}$、$n=4096$ 时：串行 Kahan 误差 **0.095**，
8 段并行（段内 Kahan、段间朴素合并）**4.095**——退化 **43 倍**，与朴素求和同级；
段间那一次朴素加法是瓶颈。但把 `small` 换回 1，串行与并行**都是 1**，
图上完全看不出差别（段和恰好是能被大数吸收的偶数倍）。
**"在我的数据上看不出差别"又一次不是证据**——它只说明这组数据不够刁。

**陷阱 4c：对数轴上"贴着地板"不等于"一直很准"。** 朴素求和在前几步也可能是精确的
（误差为 0 被地板抬起），补偿方法的曲线也贴着同一条地板。判据是曲线相对
$n u\sum\lvert x_i\rvert$ 这条界的**斜率**：$n=512$ 时朴素误差 511（界 568.43）、
Kahan 误差 1（界 2.22）；$n=4096$ 时朴素 4095（界 4547.47）、Kahan 仍是 1。
误差随 $n$ 线性增长还是不动，这才是"稳定不稳定"的分界。

**陷阱 4d：区间的宽度是 $2b$，还要加端点自己的 1 个 ulp。**
`sum_error_interval` 给的是 $\hat s \pm b$，所以宽度 $\approx 2b$；两个端点各向外推
一个 ulp。当 $b$ 远小于 $\operatorname{ulp}(\hat s)$ 时（例如 $10^{12}$ 加 11 个
$10^{-3}$ 量级的小项：$\operatorname{ulp}(10^{12})=1.22\times10^{-4}$，
Kahan 界 $2.22\times10^{-4}$，实测宽度 $7.32\times10^{-4}$），**是端点舍入在决定宽度**。
把宽度直接当成 $b$ 去和"理论界"比，会得出"区间比界宽 3.3 倍"的错误结论。

## 5. 这些陷阱的共同结构

四条，缺一条就会翻车：

1. **每个数都要有"相对谁"**：残差相对 $fl(0.3)$ 还是 $3/10$；
   $\kappa$ 是 target 还是 measured；范数是 1、2、$\infty$ 还是 F。
2. **每个对数轴都要有地板**，并且地板要在图上说明（本章帧里是 `*_floor` 元数据 +
   strings 提示），否则"0"会被读成"很小但不为 0"。
3. **每个"实测"都要有分辨率**：采样 361 点的 $\kappa$ 上限是 239.6；
   同量级的三个数看不出结合律破坏；$small=1$ 时看不出并行归约退化。
   分辨率先于结论。
4. **每个"稳定/精确"都要有限定词**：Sterbenz 只在 $b/2\le a\le 2b$ 内保证精确；
   Kahan 只保证串行；后向稳定不保证前向准。
