# 0.0 章会怎样骗你

这一章的两个可视化（阻尼振子、FTCS 热传导）都是"教科书图"，正因为太熟，最容易
让人以为自己看懂了。下面每一条都是**这个仓库里真实踩过或差点踩到**的坑，
不是泛泛而谈的注意事项。

## 1. 自适应纵轴会把发散画成收敛

阻尼振子图在过阻尼区（$\zeta>2$）的曲线尾部几乎是一条贴着零的直线，看起来"非常稳定"。
如果把纵轴自适应到数据范围，$\zeta=0$（不衰减）与 $\zeta=0.05$（缓慢衰减）在
$t=20$ 附近的振幅差可能只有一个像素，因为两者的**尾部**都被拉满到整个画面高度。
更糟的是热传导：FTCS 在 $r>r^*(n_x)$ 时是逐帧指数放大的，一旦自适应纵轴，
前 20 帧的"平稳上升"看起来像在收敛，直到最后一帧把量程撑爆、前面所有帧压成一条线。

**本项目的做法**：`axes[].autoscaled` 是 manifest 的必填字段，判断稳定性的图一律
`autoscaled: false`；越界必须给 `overflow: {flag, note}`。前端角标会直接写出
"纵轴固定 / 自适应"——不写清楚就等于骗人。

## 2. 对数误差轴让 $10^{-16}$ 和 $10^{-3}$ 长得一样

误差场默认画在双对数轴上，这是对的（要读阶），但双对数轴会**抹平数量级的直观感受**：
残差 $10^{-3}$ 与 $10^{-16}$ 都只占画面的十分之一高度。于是"残差很小"这种结论
看起来总是成立。必须同时读**数量级**：$10^{-16}$ 意味着已经到机器精度，
此时再加密网格测收敛阶只会测出噪声（本仓库的残差阶测试就是被这个坑逼出 `head=4` 的写法：
最后两个 $h$ 的实测阶是 2.03 和 2.24，看着"更准"，其实是舍入误差在主导）。

## 3. 用最低模态测稳定性是假阴性

初始条件取 $\sin(\pi x)$（最低模态）时，放大因子
$|g_1| = 1-4r\sin^2(\pi/(2(n_x-1)))$ 对任何 $r$ 都小于 1，实验会一路"稳定"到底。
真正让 FTCS 发散的模态是每格反号的那个（$\theta\to\pi$），而它在 21 个点的网格上
**根本表示不出来**——所以实测阈值 $r^*(21)=0.503097$ 才略大于 $1/2$。
用单模态做稳定性实验，等于把最危险的方向从实验里删掉了。

**本项目的做法**：C 类断言用固定种子的随机扰动做归一化幂迭代，直接测一步算子的
谱半径，并迭代到收敛；阈值附近 $|\lambda_1|$ 与 $|\lambda_2|$ 只差 $10^{-7}$ 量级，
固定步数（例如 300 步）的总增长比只有 $0.078$，看起来像稳定，其实已经发散了。

## 4. 请求时刻 ≠ 到达时刻

显式格式只能整步推进。你请求 $t=0.123$，实际到达的是 $n\Delta t$（可能差一个 $\Delta t$）。
如果图上不标出来，读者会以为"$t$ 时刻的解"是精确的。帧里带 `meta.t_actual`，
前端在时间轴上以**实到时刻**标注；`n_steps`/`dt` 也在 `meta` 里，随时可以核对。

## 5. NaN 处连线会凭空造出解

发散后数组里出现 `NaN`/`Inf`，如果渲染器把相邻有效点直连，画面上会出现一段
"看起来合理"的曲线穿过不存在的数据。**约定**：NaN 一律断线，并在图例里给出
"已断线"提示。这条在渲染层（`render2d.ts`）里实现，不是每个章节自己处理。

## 6. 把"理论临界值"当成"实测阈值"

FTCS 的经典判据 $r\le 1/2$ 是**连续极限**的结论。有限网格上的真实阈值是
$r^*(n_x)=1/(2\sin^2(\theta_{\max}/2))$，两者差 $O(\Delta x^2)$。
把 $1/2$ 直接抄成"实测值"会得到一条永远通过的断言——这正是 POLICY §3 明确禁止的
"把理论值抄回来当实测值"。本项目里 C 类断言必须二分实测，并且要把
**实测阈值与 $1/2$ 的偏差随 $n_x$ 的收敛阶**也测出来（实测 2.0894）。

## 7. 帧率丢帧被当成数值不稳定

浏览器在 60 Hz 下渲染，若模型一帧要 30 ms，时间轴会跳帧（`Timeline.droppedFrames`）。
跳帧只影响**动画的连续性**，不影响数值结果——但如果把"跳帧"误读成"解在跳"，
就会去调数值格式，方向完全错了。UI 上把丢帧数单独显示，与数值告警分开。
